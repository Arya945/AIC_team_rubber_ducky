# 🤖 AIC Intrinsic Challenge – LeRobot Simulation Project

## 📌 Overview
This project focuses on designing, simulating, and controlling an autonomous robot using **LeRobot** and **Gazebo**. The system integrates perception, decision-making (policy), and control to enable intelligent robot behavior in a simulated environment.

---

## 🎯 Objectives
- Simulate a robot in Gazebo
- Design a policy for robot decision-making
- Deploy and test using CI/CD practices
  

## AIC Evaluation Environment

## 1. Enter the AIC Evaluation Environment

Set Docker as the Distrobox container manager:

```bash
export DBX_CONTAINER_MANAGER=docker
```

Enter the `aic_eval` Distrobox container:

```bash
distrobox enter -r aic_eval
```

Start the AIC engine with ground-truth disabled:

```bash
/entrypoint.sh ground_truth:=false start_aic_engine:=true
```

---

## 2. Run the AIC Model

Run **one policy at a time**.

### WaveArm

```bash
pixi run ros2 run aic_model aic_model \
  --ros-args \
  -p use_sim_time:=true \
  -p policy:=my_policy_node_shine.WaveArm
```

### SimplePoseTargetPolicy

```bash
pixi run ros2 run aic_model aic_model \
  --ros-args \
  -p use_sim_time:=true \
  -p policy:=my_policy_node.SimplePoseTargetPolicy
```

### HybridFeedbackPolicy

```bash
pixi run ros2 run aic_model aic_model \
  --ros-args \
  -p use_sim_time:=true \
  -p policy:=my_policy_node.HybridFeedbackPolicy
```

### CheatCode

```bash
pixi run ros2 run aic_model aic_model \
  --ros-args \
  -p use_sim_time:=true \
  -p policy:=aic_example_policies.ros.CheatCode
```

> **Note:** `WaveArm`, `SimplePoseTargetPolicy`, `HybridFeedbackPolicy`, and `CheatCode` are alternative policies. Normally, start the AIC engine first and then launch the policy you want to test.

## 3. Build / Reinstall the Policy Package

After modifying `my_policy_node`, reinstall the package with:

```bash
pixi reinstall ros-kilted-my-policy-node
```

This is useful when you have changed Python code, package configuration, or other files included in the Pixi package.

---

## 4. Confirm the System Is Running

### Check object observations

```bash
pixi run ros2 topic echo /observations | grep position -A 3
```

This can be used to check whether position information is being published through `/observations`.

---

### Check robot joint states

```bash
pixi run ros2 topic echo /joint_states | grep position -A 6
```

This allows you to monitor the robot's joint positions.

---

### Check AIC model logs

```bash
pixi run ros2 topic echo /rosout | grep aic_model
```

Use this to check messages generated by `aic_model`, including errors, warnings, and status information.

---

### Check force/torque sensor data

```bash
pixi run ros2 topic echo /fts_broadcaster/wrench
```

This displays the wrench published by the force/torque sensor:

* **Force:** `x`, `y`, `z`
* **Torque:** `x`, `y`, `z`

## 5. Quick Start

The typical workflow is:

```bash
# 1. Use Docker for Distrobox
export DBX_CONTAINER_MANAGER=docker

# 2. Enter the container
distrobox enter -r aic_eval

# 3. Start AIC engine
/entrypoint.sh ground_truth:=false start_aic_engine:=true

# 4. In another terminal, enter the container
distrobox enter -r aic_eval

# 5. Run your policy
pixi run ros2 run aic_model aic_model \
  --ros-args \
  -p use_sim_time:=true \
  -p policy:=my_policy_node_shine.WaveArm
```

Then verify:

```bash
# Observations
pixi run ros2 topic echo /observations | grep position -A 3

# Joint states
pixi run ros2 topic echo /joint_states | grep position -A 6

# AIC model logs
pixi run ros2 topic echo /rosout | grep aic_model

# Force/torque sensor
pixi run ros2 topic echo /fts_broadcaster/wrench
```

## 6. Policy Development Workflow

When developing a new policy:

```text
Modify policy
     ↓
pixi reinstall ros-kilted-my-policy-node
     ↓
Restart aic_model
     ↓
Run simulation
     ↓
Check /observations
     ↓
Check /joint_states
     ↓
Check /fts_broadcaster/wrench
     ↓
Check /rosout for errors
```

### Example

If you modify:

```text
my_policy_node_shine.WaveArm
```

reinstall:

```bash
pixi reinstall ros-kilted-my-policy-node
```

Then restart the `aic_model` node using:

```bash
pixi run ros2 run aic_model aic_model \
  --ros-args \
  -p use_sim_time:=true \
  -p policy:=my_policy_node_shine.WaveArm
```

## Useful ROS 2 Topics

| Topic                     | Purpose                          |
| ------------------------- | -------------------------------- |
| `/observations`           | Environment/object observations  |
| `/joint_states`           | Robot joint positions and states |
| `/rosout`                 | ROS 2 log messages               |
| `/fts_broadcaster/wrench` | Force/torque sensor measurements |

**Important:** For vision-based evaluation with `ground_truth:=false`, `/observations` should be treated as the policy's available observation stream rather than assuming ground-truth object positions are available.
